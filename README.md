# GeoAI Outdoor Activity Recommendation Assistant

**GeoAI Hackathon @ CSRE, IIT Bombay**

An evidence-grounded AI assistant that recommends suitable nearby places and times for outdoor activities using geospatial context, weather forecasts, air-quality data, activity-specific scoring, and natural-language explanations generated by a small language model.

## 1. Project Overview

GeoAI Assistant helps users answer practical questions such as:

- Where can I go running tomorrow morning near Powai?
- Which nearby outdoor location is suitable for cycling?
- Is the air quality safe enough for outdoor exercise?
- What time is more suitable for an outdoor activity based on the weather?

Rather than relying only on generic language-model responses, the application retrieves geographic and environmental information, evaluates candidate locations and time windows, and generates recommendations supported by available evidence.

### Core Capabilities

- Natural-language outdoor activity queries
- Location resolution and nearby venue discovery
- Hourly weather and air-quality evaluation
- Activity-specific suitability scoring
- Health-profile-aware safety checks
- Relative ranking and absolute suitability classification
- Optional Qwen2.5-1.5B-Instruct explanations
- Interactive web interface with Leaflet maps
- Public FastAPI endpoints

## 2. Quickstart and Local Execution

### System Requirements

The prototype was developed and tested on:

| Component | Configuration |
|---|---|
| Operating system | Windows 11 |
| Processor | Intel Core i5-1334U |
| Architecture | x86_64 |
| Memory | 16 GB RAM |
| GPU | No dedicated GPU required |
| Python | 3.14+ in the development environment |
| Inference | CPU-based |

The development machine stores its project, virtual environment, and Hugging Face model cache on the `D:` drive. Other users may use different locations.

### Installation

Clone the source repository:

```powershell
git clone https://github.com/aajivak/GeoAI-Assistant-Prototype-V1.git
cd GeoAI-Assistant-Prototype-V1
```

Create and activate a virtual environment:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Install the project dependencies using the dependency manifest provided in the repository.

For the original development environment, the project directory is:

`D:\AI_V2\GeoAI_Assistant`

### Start the FastAPI Server

From the project root, with the virtual environment activated:

```powershell
python -m uvicorn src.api.app:app --host 127.0.0.1 --port 8000
```

Open the local application:

http://127.0.0.1:8000/

Open the local Swagger documentation:

http://127.0.0.1:8000/docs

The first language-model request may require downloading the Qwen model weights if they are not already cached.

### Public API Base URL

https://takes-wool-candidates-genuine.trycloudflare.com/

### Example Request

`POST /recommend`

```json
{
  "query": "Where can I go running tomorrow morning near Powai?",
  "search_radius_km": 5,
  "user_profile": {
    "has_asthma": false,
    "is_senior": false,
    "is_child": false,
    "is_pregnant": false,
    "notes": ""
  },
  "use_slm": false
}
```

Set `use_slm` to `true` to request a language-model-generated explanation.

### Example PowerShell Request

```powershell
$body = @{
    query = "Where can I go running tomorrow morning near Powai?"
    search_radius_km = 5
    user_profile = @{
        has_asthma = $false
        is_senior = $false
        is_child = $false
        is_pregnant = $false
        notes = ""
    }
    use_slm = $false
} | ConvertTo-Json -Depth 5

Invoke-RestMethod `
    -Uri "https://takes-wool-candidates-genuine.trycloudflare.com/recommend" `
    -Method Post `
    -ContentType "application/json" `
    -Body $body
```

## 5. Architecture and Recommendation Workflow

The system combines deterministic geospatial and environmental processing with optional small-language-model explanation generation.

**Processing pipeline:**

1. **User query:** The user describes an outdoor activity, location, and preferred time.
2. **Location resolution:** OpenStreetMap Nominatim resolves geographic references.
3. **Venue discovery:** OpenStreetMap Overpass identifies relevant outdoor locations and contextual geographic features.
4. **Environmental retrieval:** Open-Meteo supplies weather forecasts and air-quality information.
5. **Suitability evaluation:** Activity-specific rules assess candidate venue-hour combinations.
6. **Safety validation:** Health-related thresholds and environmental exclusions are applied.
7. **Ranking:** Candidate recommendations are ranked and classified.
8. **Explanation:** Qwen2.5-1.5B-Instruct optionally produces a grounded natural-language explanation.
9. **Presentation:** FastAPI returns the results to the interactive web interface.

## 8. Safety-Aware Recommendations

The recommendation engine distinguishes between relative ranking and absolute suitability.

**Relative ranking:** Orders evaluated venue-hour combinations from more suitable to less suitable.

**Absolute suitability:** Classifies recommendations using statuses such as:

- `recommended`
- `caution`
- `not_recommended`

### Environmental and Health Safeguards

The prototype incorporates rules for:

- Elevated particulate pollution during strenuous outdoor exercise
- Asthma-related air-quality sensitivity
- Heat exposure and senior-citizen considerations
- High UV exposure for children
- Pregnancy-related environmental precautions
- Adverse weather conditions

For example, high-exertion activities can be classified as unsuitable when pollution exceeds configured safety thresholds, even when a candidate ranks highest among the available options.

The prototype's heuristic thresholds are engineering choices rather than clinical standards.

## 10. Limitations and Future Improvements

### Current Limitations

- Model inference on a CPU can be slow.
- Geographic venue coverage depends on OpenStreetMap data completeness.
- Weather and air-quality forecasts may not represent exact conditions at every venue.
- Some geographic queries may return approximate locations or reference points when suitable mapped venues are unavailable.
- Suitability thresholds are heuristic and require further scientific validation.
- The public demonstration uses a temporary Cloudflare Tunnel rather than permanent cloud hosting.

### Future Improvements

- More detailed microclimate and terrain-aware modeling
- Improved venue verification and coverage
- Faster or quantized small-language-model inference
- Additional geospatial and environmental data layers
- User feedback and personalized recommendation calibration
- More extensive evaluation against observed environmental conditions
- Persistent cloud deployment
